# 웹 앱 2.1 검증 기록

검증일: 2026-10-08 (한국 시간). Windows / Python 3.12 / Node 24. 최신 기준 GitHub main `463749c`을 로컬에 fast-forward한 소스 위에서 작업했습니다. 이 기록은 웹 앱 2.1 소스와 함께 관리합니다. 실제 서버 배포 상태와는 별개입니다.

## 자동 검사

- Python **47개 전부 통과**. API 경로/입력, TAGO 파싱·페이지·오류·기한, 캐시, 서버 알림, API 소유권/Origin 검사를 포함합니다.
- JavaScript **19개 전부 통과**. 등록 노선 복원, 정류소 진행 순서, 방향 분리, 시간·요일, 여러 화면 알림, 브라우저 수신 설정 동기화, 서비스 워커 경로를 포함합니다.
- 저장된 **105개 버스번호**의 모든 유효 노선 변형이 화면에서도 정류소 순서를 유지하는지 검증했습니다. 10번·160번은 각각 두 방향으로 묶입니다.
- 알림은 시간 경계·자정 넘김·중복 감지·서버 재시작·오래된 정보·구독 만료·소유권·SSRF 제한·여러 알림 독립성을 검사했습니다.
- 느린 외부 조회 중 알림 목록/삭제가 막히지 않고, 삭제가 완료된 알림이 뒤늦게 발송되지 않는 회귀 검사를 포함합니다.
- 실제 pywebpush 암호화 경로도 호출했습니다. 최종 HTTP 전송은 모의 처리하고 OS 소켓 연결을 차단했으므로 실제 휴대폰 푸시는 보내지 않았습니다.
- JavaScript 문법 검사와 `git diff --check` 통과.

푸시 의존성은 테스트용 임시 디렉터리에만 설치했고 전역 Python 환경은 변경하지 않았습니다. 해당 의존성이 없는 기본 환경에서는 실제 라이브러리 테스트 하나가 건너뛰어집니다. 처음 제한 환경이 암호화 DLL 로딩을 차단한 실행은 실패했지만, 허용된 실행에서 전체 47개 검사를 다시 실행해 통과했습니다.

## 실제 UI·공개 데이터

- 유효한 서버 키로 10번/160번 노선과 차량의 현재 정류소를 조회했습니다. 키는 응답·화면·로그·문서에 노출하지 않았습니다.
- 지도 없이 모든 정류소를 표시하고, 실제 160번 차량의 현재 정류소와 다음 정류소가 표시되는 것을 확인했습니다. 예: MBC경남 → 삼성아파트, 덕정 → 석교(회차지). 시점에 따라 차량 수와 위치는 바뀝니다.
- 알림 버스 메뉴에 등록한 10번/160번만 표시되고, 160번 선택 시 두 방향, 방향 선택 후 그 방향의 정류소만 나타납니다.
- 출근용07:00~07:30과 귀가용18:00~18:30 알림을 각각 저장하고 새로 열어도 두 개가 유지되는 것을 확인했습니다. 테스트 알림은 검증 후 삭제했습니다.
- 새 알림 기본값07:00~07:30/매일 확인.
- 1200px 데스크톱과 390×844px 모바일에서 시각 확인. 모바일 가로 넘침 없음. 긴 정류소 이름과 저장된 알림 카드 확인.
- 서버 푸시 미설정 상태에서 '앱을 닫아도 알림 받기'가 비활성화되고 이유를 표시하는지 확인했습니다.

스크린샷:

- `verification/stops-desktop.jpg`: 실제 정류소 화면
- `verification/alarms-mobile.jpg`: 모바일 기본 알림 설정
- `verification/multiple-alarms-mobile.jpg`: 검증용 출근/귀가 두 알림 예시 (검증 후 삭제)

기존 `desktop-live.jpg` 등은 2.0 지도 버전 검증 자료이며 현재 화면이 아닙니다.

## 실제 운영에서 추가로 확인할 사항

Android 실기기 설치·닫힌 앱의 실제 푸시 수신·OS 배터리 정책·공통 HTTPS 프록시·Docker 빌드는 이 환경에서 확인하지 않았습니다. 상시 실행 서버, 영속 알림 DB, 실제 도메인과 푸시 비밀값을 설정한 뒤 실기기 도착 알림을 확인해야 합니다. 외부 서비스 배포나 ZERIONA 변경은 수행하지 않았습니다.
